Working of Networking Systems:- Networking systems operate using the OSI model:  
1. **Physical Layer:** Transmits raw bits over physical media.  
2. **Data Link Layer:** Error detection, framing (e.g., Ethernet).  
3. **Network Layer:** Routing and addressing (e.g., IP).  
4. **Transport Layer:** Reliable data delivery (e.g., TCP).  
5. **Session Layer:** Manages sessions (e.g., TLS).  
6. **Presentation Layer:** Data encoding (e.g., encryption).  
7. **Application Layer:** User-facing protocols (e.g., HTTP, MQTT).
---
operationas of L2, L3, L4 protocols, switching, routing, gateway and service discovery:
1. L2 (Data Link): Frame transmission (e.g., Ethernet, Wi-Fi).
2. L3 (Network): Routing and IP addressing.
3. L4 (Transport): Data transfer using TCP/UDP.
---
operationas of L2, L3 and L4 level security:
1. L2: MAC address filtering, VLANs.
2. L3: IPsec for encryption.
3. L4: Secure transport protocols like TLS/DTLS.
---
OSI Model Security Implementation:
1. Physical Layer: Secure physical access, encrypted transmission. (e.g., firewalls).  
2. Data Link Layer: MAC filtering, encryption, access control. (e.g., WPA, MAC address filtering, VLANs).
3. Network Layer: IPsec (Internet Protocol Security), NAT (Network Address Translation), firewalls. (e.g., VPN, ). 
4. Transport Layer: TLS/SSL (Transport Layer Security/Secure Sockets Layer), session security. (e.g., HTTPS, SFTP). 
5. Session Layer: Session protection, authentication. (e.g., Secure session tokens)
6. Presentation Layer: Encryption, data integrity checks.
7. Application Layer: Web security, application firewalls, authentication. (e.g., OAuth, JWT (JSON Web Tokens)).

Common Issues in RTOS IPC
1. Priority Inversion – A low-priority task holds a resource needed by a high-priority task.  
   - Solution: Use priority inheritance.  
2. Deadlocks – Circular resource dependencies between tasks.  
   - Solution: Use timeouts and resource ordering.  
3. Race Conditions – Multiple tasks accessing shared data without proper synchronization.  
   - Solution: Use mutexes or critical sections.  
4. Message Queue Overflow – Too many messages causing loss of data.  
   - Solution: Implement queue size limits and message discarding strategies.  
5. High Latency – Delays in message delivery due to blocking IPC mechanisms.  
   - Solution: Use non-blocking IPC methods where possible.  

Conditional Lock: Task locks a resource only when a condition(if,else,etc..) is met, preventing unnecessary blocking.
Preemption Priority: A high-priority task interrupts (preempts) a currently running lower-priority task before it completes execution.
Priority Inheritance: Mechanism used to prevent priority inversion by temporarily increasing the priority of a lower-priority task that holds a resource needed by a higher-priority task.
Deadlocks: Processes stuck in a circular wait for resources.
Concurrency: Multiple processes or threads making progress simultaneously.
Race Conditions: Multiple tasks accessing shared resources without proper synchronization.
Thread-Safe: Code or functions that operate correctly in the presence of multiple threads without introducing race conditions.
Priority Inversion: A higher-priority task waits for a lower-priority one to release resources.
Starvation: A process/thread is perpetually denied access to resources due to other higher-priority threads/processes.
Spinning: Situation where a thread or process continuously checks for a condition (e.g., waiting for a lock to be released) without releasing the CPU.
Latency: High overhead in message-passing mechanisms.

Virtual Memory in Embedded C and how can it be implemented?
Virtual memory allows programs to address more memory than what is physically available in the system by using a technique called paging or segmentation. It allows the operating system to provide an illusion of a large, continuous memory space even though physical memory may be limited.

C, C++ difference 
- C: Procedural, no OOP, no STL, supports structures.  
- C++: Supports OOP, classes, objects, STL, and advanced memory management.

ALL OOPS Concepts:
1. Encapsulation: Wrapping data and methods in a class.
2. Inheritance: Deriving new classes from existing ones.  
   Example:
   ```cpp
   class Base {
       public: void show() { cout << "Base"; }
   };
   class Derived : public Base {};
   ```
3. Polymorphism: Same interface, different implementation (overloading/overriding).  
4. Abstraction: Hiding details and exposing only essentials.

Constructors and Destructors:
1. Constructor: Initializes class objects.
   ```cpp
   class A { A() { cout << "Constructor"; } };
   ```
2. Destructor: Cleans up resources when the object goes out of scope.

What is a Class and an Object?
- **Class:** A blueprint for creating objects. It defines properties (data members) and behaviors (methods).  
   Example:
   ```cpp
   class Car {
       public:
           string brand;
           void start() { cout << "Car started"; }
   };
   ```
- **Object:** An instance of a class that holds specific values.  
   Example:
   ```cpp
   Car myCar;
   myCar.brand = "Tesla";
   myCar.start(); // Outputs: Car started
   ```
