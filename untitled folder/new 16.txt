### **1. ADC (Analog-to-Digital Converter)**  
ADC converts an **analog signal (voltage)** into a **digital value** for microcontrollers (MCUs) to process.  
- **Resolution:** Defines accuracy (e.g., 10-bit ADC = 1024 levels).   A 12-bit ADC has a resolution of (2^{12} = 4096\) discrete levels (0 to 4095).  
- **Sampling Rate:** Defines how many samples per second (e.g., 1MSPS = 1 million samples/sec).  
- **Reference Voltage (Vref):** Determines the range of input voltages.

✅ **Formula:**  
\[
\text{Digital Value} = \left( \frac{\text{Input Voltage}}{\text{Vref}} \right) \times 2^{\text{Resolution Bits}}
\]  
📌 Example: 10-bit ADC, Vref = 5V, Input = 2V → Output = `2/5 × 1024 = 409`  

---

### **2. ADC Samples**  
- **Higher samples per second (SPS)** → More accuracy but higher CPU load.  
- **Nyquist Theorem:** Sampling frequency should be **at least 2× the highest input signal frequency**.  
- **Filtering:** Use **low-pass filters** to remove noise before ADC conversion.  

✅ **Example:**  
- Audio (20 kHz) → **Minimum ADC sample rate = 40 kHz** (Nyquist).  

---

### **3. Bit Mapping ADC + MCU**  
- Bit mapping refers to mapping **ADC output bits** to a meaningful value.  
- ADC output **(binary value)** is processed to get **physical quantities (voltage, temperature, etc.)**.  
- Microcontroller (MCU) reads ADC output and maps it to **PWM, LCD display, motor control**, etc.  

✅ **Example (Temperature Sensor):**  
- 10-bit ADC, Vref = 3.3V, Temp sensor output = 0.5V per °C.  
- `ADC value = (Temperature × 0.5) / 3.3 × 1024`.  

---

### **4. Clock Generation in MCU**  
- MCUs use **crystals, PLL (Phase Locked Loop), internal oscillators** for clock generation.  
- Clock sources: **RC Oscillator (low accuracy), Quartz Crystal (high accuracy)**.  
- Higher frequency = Faster execution, but **higher power consumption**.  

✅ **Example:**  
- 16 MHz crystal with **PLL ×4** → MCU runs at **64 MHz**.  

---

### **5. Loading Firmware on Microcontroller**  
- **Firmware** is loaded into **flash memory** using tools like:  
  - **JTAG/SWD** (Debug Interface)  
  - **Bootloader (UART, USB, CAN, etc.)**  
  - **ISP (In-System Programming)**  

✅ **Example Tools:**  
- ST-Link (STM32), AVR ISP (Atmel), OpenOCD (Linux).  

---

### **6. MCU as Master/Slave Device**  
- **Master:** Controls communication, initiates data transfer.  
- **Slave:** Responds to master's commands.  

✅ **Example:**  
- **SPI:** Master sends clock (SCK), selects slave (SS).  
- **I2C:** Master generates clock (SCL), multiple slaves connected.  

---

### **7. Firmware Upgrade**  
- **OTA (Over-the-Air)** or **Bootloader-based** updates firmware without physical access.  
- Methods:  
  - **UART, USB, Ethernet, WiFi, BLE** for transfer.  
  - **Dual Bank Flash:** New firmware written to unused bank → Switch after verification.  

✅ **Example:**  
- STM32 **IAP (In-Application Programming)** for bootloader-based updates.  

---

### **8. MCU Memory: Execution/Application Code Space**  
- **Flash Memory:** Stores firmware (non-volatile).  
- **RAM:** Stores variables, stack, heap (volatile).  
- **EEPROM:** Stores non-volatile configuration data.  

✅ **Example:**  
- STM32: **Flash = 512 KB, RAM = 128 KB**.  

---

### **9. MCU Boot-Up Process**  
1. **Power-On Reset (POR).**  
2. **Bootloader execution (if present).**  
3. **Vector Table loads reset handler.**  
4. **Clock initialization.**  
5. **Main() execution.**  

✅ **Example:**  
- Cortex-M MCUs start at `0x08000000` (flash memory).

### **10. Read/Write Byte in RAM (Using Pointers)**

    char data = 0x5A;

### **11. Function Pointers in C**  
Allows calling a function dynamically.  

✅ **Example Code:**  
```c
#include <stdio.h>
void hello() { printf("Hello World\n"); }

int main() {
    void (*func_ptr)();  // Declare function pointer
    func_ptr = hello;    // Assign function address
    func_ptr();          // Call function using pointer
    return 0;
}
```

### **14. IPC: Process vs Thread**  
| **Feature**  | **Process** | **Thread** |
|-------------|------------|-----------|
| **Memory**  | Separate memory | Shared memory |
| **Communication** | IPC required | No IPC needed |
| **Speed** | Slow | Fast |
| **Example** | `fork()` creates a new process | `pthread_create()` creates a thread |

**Q: Difference between process and thread?**  
✅ **Process**: Independent execution, own memory space.  
✅ **Thread**: Runs within a process, shares memory.  

**Q: IPC (Inter-Process Communication) mechanisms?**  
✅ **Shared memory, message queues, pipes, semaphores, and sockets.**

### **16. Creation & Mounting of Basic Device Drivers in Linux**
**Q: How do you create a basic Linux device driver?**  
✅ **Steps:**  
1. Write a kernel module (`.ko`) using `module_init()` and `module_exit()`.  
2. Register the driver with the kernel.  
3. Use `insmod` to load and `rmmod` to unload.  

Example:
```c
#include <linux/module.h>
static int __init my_driver_init(void) { printk("Driver Loaded\n"); return 0; }
static void __exit my_driver_exit(void) { printk("Driver Unloaded\n"); }
module_init(my_driver_init);
module_exit(my_driver_exit);
```

---

### **17. Linux Kernel Space**
**Q: What is kernel space in Linux?**  
✅ The **privileged execution environment** where the Linux **kernel runs** (opposite to user space).  
✅ Direct access to **hardware, memory, and processes**.

### **📌 Address Space: Max & Min Values**  

**Address space** refers to the range of memory addresses a processor or system can access. It depends on the **number of addressable bits (N)** in the system.  

---

### **1️⃣ Maximum Addressable Memory (Max Address)**
The maximum address is determined by **N-bit addressing**:  
\[
\text{Max Address} = 2^N - 1
\]
✅ **Example Values:**  
| **Address Bus Size (N)** | **Max Addressable Memory (Bytes)** | **Max Address (Hex)** |
|----------------|--------------------------|----------------|
| **8-bit**  | `256` B (`2^8`) | `0xFF` |
| **16-bit** | `65,536` B (`64 KB`) | `0xFFFF` |
| **32-bit** | `4 GB` (`2^32`) | `0xFFFFFFFF` |
| **64-bit** | `16 EB (Exabytes)` (`2^64`) | `0xFFFFFFFFFFFFFFFF` |

---

### **2️⃣ Minimum Addressable Value (Min Address)**
- The **minimum valid memory address** in most architectures is `0x00000000`.  
- This represents the **starting address** of memory.  

✅ **Minimum Address:**  
```
0x00000000 (0 in decimal)
```

---

### **3️⃣ Addressable Memory vs Physical Memory**
- **Address Space** → Theoretical range (`2^N` addresses).  
- **Physical Memory** → Actual RAM present in the system (e.g., **512 MB, 8 GB**).  

---

### **📌 Summary**
- **Max Address = `2^N - 1`**
- **Min Address = `0x00000000`**
- **Depends on CPU's address bus width (`8-bit`, `16-bit`, `32-bit`, `64-bit`)**.
