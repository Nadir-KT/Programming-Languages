Common Issues in RTOS IPC
1. Priority Inversion – A low-priority task holds a resource needed by a high-priority task.  
   - Solution: Use priority inheritance.  
2. Deadlocks – Circular resource dependencies between tasks.  
   - Solution: Use timeouts and resource ordering.  
3. Race Conditions – Multiple tasks accessing shared data without proper synchronization.  
   - Solution: Use mutexes or critical sections.  
4. Message Queue Overflow – Too many messages causing loss of data.  
   - Solution: Implement queue size limits and message discarding strategies.  
5. High Latency – Delays in message delivery due to blocking IPC mechanisms.  
   - Solution: Use non-blocking IPC methods where possible.  

Conditional Lock: Task locks a resource only when a condition(if,else,etc..) is met, preventing unnecessary blocking.
Preemption Priority: A high-priority task interrupts (preempts) a currently running lower-priority task before it completes execution.
Priority Inheritance: Mechanism used to prevent priority inversion by temporarily increasing the priority of a lower-priority task that holds a resource needed by a higher-priority task.
Deadlocks: Processes stuck in a circular wait for resources.
Concurrency: Multiple processes or threads making progress simultaneously.
Race Conditions: Multiple tasks accessing shared resources without proper synchronization.
Thread-Safe: Code or functions that operate correctly in the presence of multiple threads without introducing race conditions.
Priority Inversion: A higher-priority task waits for a lower-priority one to release resources.
Starvation: A process/thread is perpetually denied access to resources due to other higher-priority threads/processes.
Spinning: Situation where a thread or process continuously checks for a condition (e.g., waiting for a lock to be released) without releasing the CPU.
Latency: High overhead in message-passing mechanisms.

Q. Memory leak
A. Memory Leaks: Occur when allocated memory is not freed, causing the program to consume more memory over time.
		A memory leak occurs when a program allocates memory dynamically (e.g., using malloc, calloc, realloc, or similar functions in C) but fails to release it using free, resulting in memory that cannot be reused by the program or the operating system. Over time, memory leaks can lead to reduced performance or cause the program to crash due to memory exhaustion.
		void leak() {
			int *ptr = malloc(sizeof(int) * 100); // Allocated memory
			// No free(ptr); Memory is leaked
		}
		
		Fix/Prevention - Ensure all allocated memory is freed.
		
5.	What is Segmentation Fault in C ?
A.	A Segmentation Fault (often abbreviated as segfault) occurs when a program tries to access a memory location that it is not allowed to access. It is a runtime error related to memory access violations.
Cause	- Dereferencing invalid or null pointers. - Accessing freed memory.
int *ptr = NULL;
*ptr = 5; // Dereferencing a NULL pointer leads to a segmentation fault.

	Buffer Overflow: Writing data beyond the bounds of allocated memory. Cause - Writing beyond or before the boundaries of an array.
	char buffer[10];
	strcpy(buffer, "This string is too long!"); // Overflows buffer

	Buffer Overflow Prevention: Always ensure memory operations stay within bounds using functions like memcpy() or strncpy() with proper size checks.
	Fix/Prevention - Always validate buffer boundaries. - Use secure functions like strncpy instead of strcpy. - Enable compiler warnings.
	
	Double Free: Freeing the same memory block twice, which can lead to undefined behavior.

	Limit Heap Usage (Dynamic Memory Allocation) in Embedded Systems: Heap memory can be unpredictable and lead to fragmentation in resource-constrained systems.
	Prefer Stack for Temporary Data: Use stack memory for temporary variables as it is automatically managed and faster than heap allocation.
	
Stack Overflow: When a program's call stack exceeds its limit, causing the program to crash.
Cause - Excessive recursion. - Very deep or infinite loops using local variables. - Creating too many local variables or very large ones.
Fix/Prevention - Avoid deep recursion. - Optimize the use of stack memory. - Increase stack size if necessary.
void recursive() {
    recursive(); // Infinite recursion leads to stack overflow
}
Fixes/Prevention	- Check pointers for null before dereferencing. - Avoid using dangling pointers.
	
9. Dangling pointer

	The memory it refers to is no longer valid, leading to undefined behavior if accessed.
	How Dangling Pointer Occurs:
		Deleting a memory block (e.g., using free() or delete) without setting the pointer to NULL.
		Returning the address of a local variable from a function.
		Overwriting a pointer's value without proper cleanup.
	Issue: If you try to dereference a dangling pointer, it results in undefined behavior, which could cause a crash or corrupt data.

How memory will be allocate in linked list and advantage
	memory for each node is allocated dynamically, which means each node is created and stored in the heap memory as the list grows. A linked list doesn't require memory to be contiguous (unlike arrays), so each node can be placed anywhere in memory.
	Each node of a linked list typically contains:
		Data: The actual data that the node holds (e.g., integer, string).
		Next Pointer: A pointer that references the next node in the list.
	Advantages of Linked List Memory Allocation:
		Dynamic Memory: The size of a linked list can grow and shrink dynamically, without needing to allocate memory ahead of time.
		No Fragmentation: Since nodes are allocated separately, there is no need for contiguous memory blocks (as in arrays).
		Efficient Memory Usage: Only as much memory as needed for the nodes is used, whereas in arrays, memory might be wasted if the array isn't fully populated.

#include <stdio.h>
#include <pthread.h>

#define MAX_NUM 10  // Change this to print more numbers

pthread_mutex_t lock;
pthread_cond_t cond;
int counter = 1;  // Shared counter

void *print_odd(void *arg) {
    while (counter < MAX_NUM) {
        pthread_mutex_lock(&lock);
        while (counter % 2 == 0)  // Wait if it's not an odd number
            pthread_cond_wait(&cond, &lock);

        printf("Odd: %d\n", counter++);
        pthread_cond_signal(&cond);  // Wake up the even thread
        pthread_mutex_unlock(&lock);
    }
    return NULL;
}

void *print_even(void *arg) {
    while (counter <= MAX_NUM) {
        pthread_mutex_lock(&lock);
        while (counter % 2 != 0)  // Wait if it's not an even number
            pthread_cond_wait(&cond, &lock);

        printf("Even: %d\n", counter++);
        pthread_cond_signal(&cond);  // Wake up the odd thread
        pthread_mutex_unlock(&lock);
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;

    pthread_mutex_init(&lock, NULL);
    pthread_cond_init(&cond, NULL);

    pthread_create(&t1, NULL, print_odd, NULL);
    pthread_create(&t2, NULL, print_even, NULL);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);

    pthread_mutex_destroy(&lock);
    pthread_cond_destroy(&cond);

    return 0;
}
